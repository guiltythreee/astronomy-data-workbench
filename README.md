# Astronomy Data Workbench (ADW)

A standalone, local-first Python tool that inspects, validates and audits astronomical
catalogue files **before** any application (such as Star Map) consumes them.

> Parsing a file successfully is not the same as the data being scientifically right.
> ADW records where data came from, checks it, explains every problem row, and never
> modifies the source file.

**Status:** foundation + BSC TSV ingestion/validation, with partial Coordinate Accuracy Laboratory and Star Identity Explorer implementations. Cross-matching is partly built and **UNVERIFIED** (synthetic data only); see `docs/crossmatching.md`.

## The five modules

| # | Module | Status |
|---|---|---|
| 01 | Catalogue Acquisition Manager | partial (local-file manifest + SHA-256) |
| 02 | Star Catalogue Validator | available (BSC TSV) |

## Install

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest
```

Requires Python 3.12+, NumPy and Astropy for the coordinate laboratory. Install with `pip install -e ".[dev]"`.

## Use

```bash
adw inspect my_bsc_export.tsv                       # what is in this file?
adw validate bsc-tsv my_bsc_export.tsv              # BSC validation
adw validate hip2-tsv my_hipparcos2_export.tsv      # Hipparcos-2 validation
adw export bsc-tsv my_bsc_export.tsv --out adw-out  # write the audit bundle
adw audit adw-out --source my_bsc_export.tsv        # re-verify checksums
adw modules                                         # list the modules and their status
adw coords-lab --out coords-report.json             # coordinate reference suites (NumPy/Astropy)
adw explorer --out identity-explorer.html           # local explorer (bundled records are synthetic)
adw crossmatch demo --out demo-out                  # UNVERIFIED: synthetic cross-match scenarios
```

Try it now on the synthetic fixture (invented values, not real catalogue data):

```bash
adw validate bsc-tsv tests/fixtures/bsc_synthetic.tsv
```

### What `export` writes

| File | Content |
|---|---|
| `accepted.jsonl` | rows that passed every check, with normalized values **and** the raw cells |
| `review.jsonl` | parseable but suspicious rows, with reasons |
| `rejected.jsonl` | unusable rows, with reasons and source line numbers |
| `issues.csv` | one line per issue |
| `report.md` | human-readable summary |
| `audit.json` | input SHA-256, versions, config, counts, issue codes, output checksums |

Outputs contain no timestamps (only `audit.json` does), so the same input, config and version
always give byte-identical outputs and the same `content_checksum`.

### Hipparcos-2 validation (I/311/hip2)

```bash
adw inspect my_hipparcos2_export.tsv
adw validate hip2-tsv my_hipparcos2_export.tsv
adw validate hip2-tsv my_hipparcos2_export.tsv --jsonl hip2-validated.jsonl
```

The Hipparcos-2 validator requires `HIP`, `RArad`, and `DErad`; it recognizes the 16-column
export profile documented in `docs/validation-policy.md`. Positions are ICRS at epoch J1991.25;
`RArad` and `DErad` are degrees despite the `RArad` field name. Parallax is signed and negative
measurements are informational, not failures. Large proper motions are retained without an
arbitrary upper limit. Real-data validation remains pending until the supplied I/311/hip2 TSV is
run through this command.

## Key conventions (BSC)

- Positions: FK5, equinox J2000, epoch J2000.0.
- `pmRA` is already mu_alpha* (includes cos dec); it is never multiplied by cos dec again.
- arcsec/yr and arcsec become mas/yr and mas by an explicit ×1000 only.
- Missing or malformed values are flagged, never silently turned into defaults.

See `docs/` for the full policy.

## Single-file tool builds

Five single-file Python archives are generated by `python build_single_file_tools.py` into `dist/`:

- `01-catalogue-acquisition-manager.pyz` — local-file provenance manifest and SHA-256.
- `02-star-catalogue-validator.pyz` — BSC TSV validator.
- `03-astronomical-cross-matching-workbench.pyz` — epoch-corrected positional matching; **UNVERIFIED** on synthetic data only.
- `04-coordinate-accuracy-laboratory.pyz` — coordinate reference suites and JSON report.
- `05-star-identity-explorer.pyz` — local HTML explorer (bundled sample data is synthetic).

Run an archive with `python path/to/tool.pyz --help` where supported. The coordinate laboratory requires the declared NumPy and Astropy dependencies in the Python environment. The five archives include the ADW Python package source but do not vendor third-party dependencies.

These are one-file launchable bundles, not a claim that every planned capability is complete. In particular, the acquisition tool does not download catalogues, and cross-matching has not been validated against real BSC, Hipparcos or Gaia records.
